# Domain docs

This is a single-context repository. Before exploring or changing domain behavior, read the root `CONTEXT.md` and the relevant ADRs under `docs/adr/`.

Use the glossary's canonical terms in issues, specs, implementation, and tests. Surface conflicts with an existing ADR explicitly instead of silently overriding it. Missing domain documentation is created lazily through the domain-modeling workflow when a term or decision is resolved.
