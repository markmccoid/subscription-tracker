# Skipped weeks are occurrence plans

A user skipping one week of a weekly Subscription will be recorded as a Skipped Week against that projected Billing Date rather than as a Lifecycle Event pair. Meal-kit style commitments are skipped routinely, so representing each skip as a pause and a resume would flood Subscription Activity with transitions that describe delivery choices rather than changes to the commitment itself, and would force the Billing Schedule to be rewritten every time a week is toggled. Keeping skips out of the lifecycle leaves projection a pure function of the schedule, so a skip can be freely added or removed while its Billing Date is still in the future.

Once a Skipped Week's Billing Date passes, its Billing Occurrence materializes and is resolved by a Generated Charge Exception with the reason `Skipped week`, linked to the Skipped Week so that removing the skip reconciles only its own consequence — the same linkage ADR-0004 established for Lifecycle Events. This keeps a planned skip out of Action Needed while preserving the retained history ADR-0003 depends on, and it gives the user an explicit correction path when the provider charged for a week that was planned as skipped.
