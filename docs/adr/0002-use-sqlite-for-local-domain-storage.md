# Use SQLite for local domain storage

Version one will use Expo SQLite as the authoritative store for the Household List because Subscriptions, Payments, Charge Exceptions, Payment Methods, and lifecycle history require relational integrity, migrations, historical queries, and atomic updates. Domain behavior will depend on a repository boundary rather than SQLite directly so a future Convex-backed repository can be introduced without reshaping the domain model; MMKV may hold non-domain preferences but will not hold authoritative domain data. Portable Backups will be versioned semantic JSON produced and restored through the repository rather than copies of the SQLite database, and a restore must validate and migrate the complete Backup before replacing existing data in one transaction.
